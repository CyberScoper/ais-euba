# Index

Неофициальный клиент **AIS2 Экономического университета в Братиславе** (`ais2.euba.sk`): расписание,
предметы и оценки, платежи и сообщения на одном экране, который открывается на телефоне меньше чем за
секунду. Это PWA с маленьким Node-сервером за ней, и она рассчитана на собственный хостинг — один
экземпляр на человека или на компанию людей, которые друг другу доверяют.

## Что умеет

- **Сегодня** — пара, которая идёт прямо сейчас, или ближайшая, сколько вы должны и что лежит во
  входящих. До начала семестра экран говорит, когда он начнётся, вместо того чтобы быть пустым.
- **Расписание** — на десктопе неделя сеткой, в телефоне по дням. У лекций и семинаров свои цвета;
  свободный день показывает ближайший день, который не свободен.
- **Предметы** — записанные предметы, кредиты, оценки и средневзвешенный балл, плюс план обучения.
- **Финансы и сообщения** — платежи вместе с переменным символом, а рядом лента сообщений из AIS:
  большая их часть всё равно про платежи.
- **Университет** — практические вещи, которых в AIS нет: транспорт от общежитий, столовые,
  библиотека, продление ISIC, университетская почта.
- **Четыре языка** — словацкий, русский, украинский и английский, у каждого свои правила
  множественного числа и формы дат. То, что присылает сам AIS (названия предметов, категории
  сообщений), остаётся словацким, и приложение прямо об этом говорит.
- **Ставится как приложение** — это настоящая PWA: она сама предлагает установку, оболочка работает
  офлайн, а данные — нет, потому что оценка из кэша это неправильная оценка.

## Как это устроено

У AIS нет публичного API, а его CORS-политика исключает обращение из браузера. Поэтому здесь
**прокси на сервере** — не расширение для браузера и не инструмент в духе «вставьте сюда свою cookie»:

<p align="center">
  <img src="docs/readme/flow.svg" alt="PWA говорит с этим Node-сервером, он держит сессию AIS и читает ais2.euba.sk" width="100%">
</p>

Цепочка авторизации та же, что у официальной Angular-SPA: POST на `/ais/login.do` за `JSESSIONID`,
токен из `/ais/rest/apps/get-access-token`, и дальше каждый REST-вызов несёт и то, и другое. Сервер
обновляет токен, когда тот стареет, и перелогинивается не чаще раза в минуту.

Пароль от AIS нужен для входа и после этого живёт **в памяти сервера**. Если поставить галочку
«оставаться в системе», он дополнительно сохраняется зашифрованным (AES-256-GCM) в каталоге
состояния, а ключ лежит рядом в файле с правами `0600`. Это защищает от украденной резервной копии, а
не от того, кто уже получил доступ к машине, — и экран входа говорит об этом именно такими словами,
до того как вы начнёте печатать.

### Вежливый клиент

Всё, что уходит наверх, проходит через один регулятор: минимальный промежуток между вызовами,
потолок в минуту, джиттер, склейка одинаковых одновременных чтений в один запрос и кэш со своим
сроком жизни для каждого эндпоинта (расписание живёт пятнадцать минут). Повторяющиеся неудачные входы
останавливает предохранитель, заведённый **на каждый аккаунт отдельно**: именно долбёжка неверным
паролем и приводит к блокировке аккаунта в AIS.

## Запуск

```bash
npm install
AIS_MOCK=1 npm start     # демо-данные, аккаунт AIS не нужен — http://localhost:4173
npm start                # боевой режим, вход данными от AIS2
```

На сервере всё делает `deploy/deploy.sh` — systemd-юнит, nginx-vhost, Let's Encrypt:

```bash
DOMAIN=ais.example.com LE_EMAIL=you@example.com deploy/deploy.sh
```

Приложение слушает только localhost; TLS терминируйте перед ним.

| Переменная | По умолчанию | Что это |
| --- | --- | --- |
| `PORT` | `4173` | порт, который слушать |
| `AIS_BASE` | `https://ais2.euba.sk` | адрес AIS |
| `AIS_LNG` | `SK` | язык, на котором отвечает AIS |
| `AIS_SECRET` | — | ключ для шифрования запомненных паролей (64 hex-символа или парольная фраза); иначе ключ сгенерируется в файл |
| `AIS_STATE_DIR` | `/var/lib/ais-pwa` | где лежат сессии и этот ключ |
| `AIS_SESSION_DAYS` | `30` | сколько живёт запомненная сессия |
| `AIS_GA_ID` | — | идентификатор аналитики для этого экземпляра, если она вообще нужна |
| `AIS_MOCK` | — | `1` — демо-данные, AIS не трогается вовсе |
| `AIS_RAW` | — | `1` включает read-only passthrough для калибровки адаптеров; в бою держите выключенным |

## Что где лежит

```
server/aisClient.js     цепочка авторизации AIS, REST и нормализация ответов
server/security.js      заголовки, лимиты, проверка источника, безопасность путей
server/guard.js         регулятор, склейка вызовов, кэш, предохранитель на вход
server/sessionStore.js  сессии на диске и запечатанный пароль за «оставаться в системе»
server/index.js         express: сессии, чистый /api/*, раздача статики
public/                 сама PWA — без сборки, без фреймворка, без бандлера
public/i18n.js          каждая фраза на четырёх языках, со своими правилами чисел
scripts/handbook/       исходники экрана «Университет»; public/handbook.js генерируется
```

## Безопасность

- cookie сессии — `HttpOnly`, `SameSite=Lax`, `Secure`, 192 бита энтропии, скользящий срок жизни;
  меняющие состояние запросы с чужого источника отклоняются сразу;
- строгая Content-Security-Policy с `frame-ancestors 'none'` и без единого инлайн-скрипта;
- `Cache-Control: no-store` на каждом ответе API;
- лимиты по IP перед API и более жёсткий перед формой входа;
- passthrough разрешает пути в AIS **поимённо** и отклоняет всё, где есть `..`: у AIS деструктивные
  операции доступны обычным `GET`, так что запрещать по методу было бы недостаточно;
- перехваченные реальные ответы AIS (для офлайн-QA) лежат в `.gitignore` и никогда не попадали в
  коммиты.

Нашли дыру? См. [SECURITY.md](SECURITY.md).

## Чем это не является

Это **не проект университета, он его не одобрял и никак с ним не связан**. Клиент читает те же
данные, что и официальный клиент AIS2, вашими же учётными данными, на сервере, который контролируете
вы, и никогда ничего не записывает в AIS: любой вызов — чтение.

Экран «Университет» — это снимок публичных страниц Студенческого парламента, пересказанный своими
словами, со ссылкой на источник и датой последней сверки на каждой карточке. Это не зеркало текста
университета, и если данные разойдутся, правы страницы университета.

Если сервер держите не вы, вы доверяете свой университетский пароль тому, кто его держит. Это
реальная цена, и честный совет — поднять свой экземпляр.
